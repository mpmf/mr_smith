# Time-Ordered Session IDs (UUID v7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate session IDs as RFC 9562 version 7 UUIDs so the sessions directory sorts chronologically by creation time.

**Architecture:** Add a small `UuidV7` utility class that builds a v7 UUID from a 48-bit Unix-epoch millisecond timestamp plus 62 random bits, with version `0111` and variant `10` bits set. Replace the single `UUID.randomUUID()` call site in `ChatSession.startNewSession()` with `UuidV7.random()`. No new dependencies (Java 21 has no built-in v7 generator).

**Tech Stack:** Java 21, JUnit 5 (Jupiter), Maven.

- [ ] **Step 3: Write minimal implementation**

Create `src/main/java/com/mrsmith/chat/UuidV7.java`:

```java
package com.mrsmith.chat;

import java.util.Random;
import java.util.UUID;

final class UuidV7 {

    private static final Random RANDOM = new Random();

    private UuidV7() {
    }

    static UUID random() {
        long ms = System.currentTimeMillis();
        long top = (ms << 16) | 0x7000;
        long bottom = (RANDOM.nextLong() & 0x3FFFFFFFFFFFFFFFL) | 0x8000000000000000L;
        return new UUID(top, bottom);
    }
}
```

Note: the `0x7000` sets the version nibble to `0111` at bits 48-51 of the top
long. The bottom long is masked to clear the two variant bits (bits 64-65 of
the UUID), then bit 63 is OR'd high so the result reads as RFC 4122 variant
(`10`, `variant() == 2`). `System.currentTimeMillis()` guarantees two ids
generated in different milliseconds sort strictly; same-ms ids tie on the
prefix and rely on the random low bits (accepted per spec).
